# Concurrent Update Protection in Go

Практический стенд на Go для изучения защиты данных от `Lost Update`
при одновременном изменении одного ресурса несколькими клиентами.

Проект позволяет на реальных конкурентных HTTP-запросах сравнить три
стратегии управления конкурентностью:

- Optimistic Locking через PostgreSQL;
- Pessimistic Locking через `SELECT FOR UPDATE`;
- Distributed Lock через Redis.

Проект разворачивается в Kubernetes и предназначен для разработчиков,
которые хотят понять, как разные механизмы блокировки влияют на поведение
распределенного backend-сервиса.

## Что дает этот проект

После запуска проекта можно самостоятельно увидеть, чем отличаются
три подхода к защите общего ресурса:

- `Optimistic Locking` обнаруживает конфликт изменения версии;
- `Pessimistic Locking` заставляет конкурирующие операции ждать;
- `Redis Lock` позволяет блокировать ресурс на уровне распределенного
  приложения до обращения к базе данных.

Для проверки используются реальные конкурентные HTTP-запросы, поэтому
результат каждой стратегии можно наблюдать непосредственно по HTTP-ответам.

## Что можно изучить

- предотвращение `Lost Update`;
- optimistic concurrency control;
- PostgreSQL transactions;
- `SELECT FOR UPDATE`;
- атомарное обновление по версии;
- распределенные блокировки Redis;
- HTTP `409 Conflict`;
- HTTP `423 Locked`;
- конкурентные запросы в Go;
- запуск backend-сервиса в Kubernetes.
